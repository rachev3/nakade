# apps/web — Frontend

React SPA for nakade. Spec and decisions: [docs/frontend.md](../../docs/frontend.md). Owner: rachev3.

> **Everything runs on mock data for now.** The backend doesn't exist yet, so [MSW](https://mswjs.io)
> intercepts `/api/*` in the browser and serves hand-written fixtures. A **"Demo data"** badge is
> shown app-wide, and every fact from a fixture is tagged **DEMO** instead of verified/calculated/estimate.
> The numbers are placeholders, not facts about the real places.

## Run it

Requires Node ≥ 22 and pnpm (version pinned in the root `package.json`, `corepack enable` picks it up).

```bash
pnpm install          # from the repo root
pnpm dev              # http://localhost:5173
```

Other scripts (run from the repo root, or inside `apps/web` without `--filter`):

| Command                                | What                                                                           |
| -------------------------------------- | ------------------------------------------------------------------------------ |
| `pnpm --filter @nakade/web build`      | Typecheck + production build into `dist/`                                      |
| `pnpm --filter @nakade/web preview`    | Serve the built `dist/`                                                        |
| `pnpm --filter @nakade/web lint`       | ESLint (includes the "features never import each other" rule)                  |
| `pnpm --filter @nakade/web typecheck`  | `tsc -b`                                                                       |
| `pnpm --filter @nakade/web format`     | Prettier                                                                       |
| `pnpm --filter @nakade/web api:types`  | Regenerate `src/api/schema.d.ts` from `openapi.yaml`                           |
| `pnpm --filter @nakade/web deploy:dev` | Build and deploy to dev.nakade.app by hand (normally Workers Builds does this) |

Language: Bulgarian by default. Switch with the BG/EN button or `?lng=en`.

## How the mocks work

```
src/api/
  openapi.yaml        DRAFT contract (frontend-written, follows docs/proposals/backend.md)
  schema.d.ts         generated by openapi-typescript, don't edit
  types.ts            friendly aliases for the generated types
  client.ts           openapi-fetch client (sends Accept-Language)
  queries.ts          TanStack Query hooks
  config.ts           API_MODE: mock | live
  mocks/
    fixtures.ts       5 towns + 2 villages. PLACEHOLDER values, source = "demo"
    db.ts             fake server-side persistence (localStorage): profile, swipes
    matcher.ts        toy deterministic scoring (NOT the real algorithm)
    narratives.ts     template simulation + plan, scenes tagged fact | scenario
    handlers.ts       MSW request handlers for every endpoint
    browser.ts        starts the service worker
```

- `src/main.tsx` starts MSW before rendering when `API_MODE === 'mock'`. This is the default, in
  local dev **and** in the deployed build, until the backend exists.
- `public/mockServiceWorker.js` is the MSW worker script (`npx msw init public`), served next to the app.
- Mock state lives in `localStorage` (`nakade.mock-db.v1`), so a reload keeps your profile, swipes and
  saved places, like the real session cookie will. To start over, clear site data.

### Switching to the real API

1. The backend publishes its OpenAPI spec. Replace `src/api/openapi.yaml` with it (or point
   `api:types` at it) and run `pnpm api:types`. Fix any type errors: those are the contract changes.
2. Build with `VITE_API_MODE=live`. MSW is then not loaded and the "Demo data" badge disappears.
3. The web Worker proxies `/api/*` to the backend (to be added to `wrangler.jsonc` when the backend
   is hosted).

## Structure

```
src/
  app/          router (data mode, lazy routes), providers, layout, error page
  features/     start (landing + journeys), onboarding, discover, place, simulation, compare (+ saved), plan
  components/   shared UI: Fact, Scenario, ScoreBar, DemoBadge, UpgradeCard, MapView, ui/ (shadcn)
  api/          see above
  lib/          i18n, journey + theme stores (Zustand), formatting, cn()
  styles/       tokens.css (light/dark design tokens), index.css (Tailwind v4 entry)
  locales/      bg/, en/
```

Rule: `features/*` import from `components/`, `api/` and `lib/`, never from each other (enforced by ESLint).

### Trust UI

- `<Fact>` renders an API fact with its status (verified / calculated / estimate, or "No reliable
  data" for `null`) and provenance in a popover. Demo facts show **DEMO** instead of a status.
- `<Scenario>` renders imagined narrative: tinted, italic, labelled "Imagined".

### Styling

Visual direction: **"Rodopi calm"**. It's warm, earthy and editorial: forest green and clay on cream, with a "forest night" dark theme. Headings use Lora; everything else uses Sofia Sans, a Bulgarian typeface with Bulgarian Cyrillic forms. Both fonts are self-hosted via Fontsource, so no Google Fonts requests are made. All colours live in `src/styles/tokens.css` (`:root` = light, `.dark` = dark), and components only use semantic names (`bg-primary`, `text-clay`, `text-fact-verified`, …). Swipe cards and place pages use a generated `<Landscape>` illustration until we have licensed photos. shadcn/ui components live in `src/components/ui` (`components.json` is set up, so `pnpm dlx shadcn@latest add <name>` works).

## Deploy

`wrangler.jsonc` in this folder. Static assets from `dist/`, SPA fallback. `public/_headers` adds
`X-Robots-Tag: noindex` on dev.nakade.app. Builds and environments: [docs/devops.md](../../docs/devops.md).
